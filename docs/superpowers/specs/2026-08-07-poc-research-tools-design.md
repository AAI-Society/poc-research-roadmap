# Design — Rust research tools for P01, P02 and P05

**Date:** 2026-08-07 · **Status:** approved, ready for implementation planning

---

## Summary

Three private repositories in the `Task-force-for-AI-agents-in-Healthcare` GitHub organization,
one per prioritized paper. Each holds a Rust tool that produces the paper's central artifact, and
a LaTeX paper in the Advanced AI Society format used by `ov-poc-standard/paper/`.

| Repo | Binary | Paper | What the tool does |
| --- | --- | --- | --- |
| `parallax` | `parallax` | [P01](../../../papers/P01-trust-calculus.md) | Computes a residual trust set from a deployment description |
| `transit` | `transit` | [P02](../../../papers/P02-effect-binding.md) | Tests whether an endpoint satisfies the effect-binding conditions |
| `occultation` | `occultation` | [P05](../../../papers/P05-unlinkable-identity.md) | Measures what unlinkability costs at agent action rates |

The names come from observational astronomy, where each describes the tool's method: **parallax**
determines depth by observing from two positions, which is exactly the independent-encoding check;
**transit** infers a hidden body's properties from what it does to light passing through, which is
how the prober learns endpoint behaviour; **occultation** is one body deliberately passing in front
of another to hide it, which is the unlinkability property itself.

## Goals

1. Each tool produces its paper's headline result, runnable by a third party.
2. Everything that is not real is marked as modelled, following the convention in
   `ov-poc-standard/impl/README.md`, which separates "what is real and what is modelled" explicitly.
3. Measured numbers flow from tool output into the paper, so a stale figure cannot outlive a code
   change.
4. Nothing in the repositories sends unauthorized traffic to systems the operator does not own.

## Non-goals

* Novel cryptography. `occultation` benchmarks and composes existing primitives; the ECDAA and
  threshold-escrow constructions that P05 proposes are research output, not tool output.
* Complete paper drafts. Sections that depend on experiments not yet run stay placeholdered.
* Publishing to crates.io. Repositories are private initially.

## Shared skeleton

Identical across all three repositories so that a contributor who learns one knows the others.

```
├── Cargo.toml              workspace: library crate + binary crate
├── src/lib.rs              the library others build on
├── src/bin/<name>.rs       the CLI
├── tests/                  integration tests, including headline-result assertions
├── benches/                criterion benchmarks
├── examples/               runnable input files
├── results/                tool output consumed by the paper; committed, and regenerated by CI
│                           so a stale number cannot outlive a code change
├── paper/main.tex          Advanced AI Society branded, builds with tectonic
├── paper/references.bib
├── paper/README.md         build instructions and pre-submission checklist
├── .github/workflows/ci.yml    fmt · clippy -D warnings · test · paper build
├── LICENSE-APACHE
├── LICENSE-CC-BY-4.0
└── README.md               includes a "What is real and what is modelled" section
```

**Rust conventions.** Edition 2021. Errors: `thiserror` in library crates, `anyhow` in binaries.
Non-zero exit codes on policy violations so all three drop into CI pipelines. No panics on
malformed input — asserted by test, since two of the three tools consume hostile input by design.
CLI parsing with `clap` derive. Serialization with `serde`.

**Licensing.** `ov-poc-standard` is CC BY 4.0, which is correct for specification text and wrong
for code — Creative Commons recommends against CC licenses for software, as they carry no patent
grant and no software-tuned warranty disclaimer. Each repository therefore carries **Apache-2.0 for
the Rust code** and **CC BY 4.0 for `paper/`**, stated in the README. Copyright is held by Advanced
AI Society and the Proof-of-Control contributors, matching the existing repositories.

## parallax — P01 trust calculus

### Purpose

Take a deployment description and compute the set of parties whose dishonesty would change the
answer, together with the latency within which each party's misbehaviour becomes detectable.

### The engine decision

P01 proposes SLG resolution with tabling, in the style of XSB, to prevent circular delegation and
mutual attestation from diverging. Rust offers a cleaner route.

Represent the residual trust set as a **lattice element**: a set of `(principal, capability,
latency)` assumptions ordered by inclusion, with join defined as union. Use `ascent` 0.8, whose
lattice-valued relations compute a least fixpoint by semi-naive evaluation. Because the principal
set declared in a deployment is finite, the powerset lattice is bounded, so the fixpoint always
converges.

**Termination falls out of the datatype rather than the resolution strategy.** This is a stronger
and simpler result than the paper currently claims, and it should be folded back into P01's
mechanization section.

Detection latency composes as its own small lattice:

```rust
enum Latency { Bounded(Duration), Never }
// join: Never absorbs; Bounded(a) ⊔ Bounded(b) = Bounded(max(a, b))
```

### Data model

Input is TOML. A deployment declares principals, the mechanisms in use, and how mechanisms compose:

```toml
[[principal]]
id = "did:web:intel.com"
role = "SiliconManufacturer"

[[mechanism]]
kind = "tee_attestation"          # tee_attestation | signing | hash_chain | anchoring
                                  # | gossip | witness_quorum | zk_proof
endorser = "did:web:intel.com"
collateral_authority = "did:web:pcs.intel.com"
collateral_refresh = "12h"
reference_values = "did:web:example.org/rvp"
```

Each mechanism kind has a composition rule contributing assumptions with latencies. Output is the
Residual Trust Manifest as JSON-LD, matching the schema P01 proposes for C7.4 / C10.2, plus a
human-readable table.

### Commands

| Command | Purpose |
| --- | --- |
| `parallax solve <deployment.toml>` | emit the Residual Trust Manifest |
| `parallax explain <deployment.toml> -p <principal>` | proof tree showing why a principal is load-bearing |
| `parallax compare <a.toml> <b.toml>` | report `⊆`, `⊇`, `=` or `INCOMPARABLE` |
| `parallax diff <a.toml> <b.toml>` | assumption-level diff, for the independent-encoding experiment |
| `parallax check <manifest.json> --policy <p.toml>` | C10.3 evaluation; exit 1 if the manifest exceeds policy |

### Examples shipped

`examples/` contains Σ₁ software-only, Σ₂ Intel TDX, Σ₃ witness quorum (5-of-7), Σ₄ ZK rollup, and
Σ₅ a TEE+ZK hybrid.

### Acceptance tests

1. `solve` on Σ₂ produces the five-party TDX trust set that was derived by hand, from the
   deployment description alone, without those parties being enumerated in the encoding.
2. `compare` on Σ₂ and Σ₄ reports `INCOMPARABLE`. This is the paper's headline result.
3. **`solve` on Σ₅ identifies the shared compiler toolchain and reference-value provider across
   both the TEE and ZK layers.** If the tool cannot rediscover this, it has not earned its place in
   the paper.
4. A deployment with circular delegation terminates and produces a finite trust set.

## transit — P02 effect binding

### Purpose

Determine whether a given endpoint satisfies the four conditions under which binding a message
binds an effect: parameter completeness (C1), representation injectivity (C2), strict idempotency
(C3), and contextual state pinning (C4).

### Components

**`hostile-server`** — a mock HTTP server implementing every failure mode deliberately:
last-key-wins duplicate handling, hidden profile-derived parameter defaults, URI aliasing
(`/v1/users/me` resolving to a concrete id), non-idempotent POST, and no state pinning. Each
failure mode is individually toggleable. This makes every other component runnable offline with no
credentials and no third-party traffic.

**`differential`** — the central component and the one that demonstrates the attack. Runs a single
payload through `serde_json`, a strict I-JSON parser written for this crate, and any of
node / python3 / go / ruby found on the host, then reports where they disagree. **Touches no
network at all.** The Go last-key-wins versus Elixir first-key-wins split is the case to
reproduce.

**`fuzz`** — generates the adversarial corpus: duplicate keys, lone surrogates, NFC/NFD pairs,
negative zero, `1e-400` underflow, integers beyond 2^53, and percent-encoding variants.

**`classify`** — consumes an OpenAPI document and optional probe results, classifies the endpoint
against C1–C4, and emits `Qualified` / `Conditional` / `Non-qualifying` with the specific condition
that failed.

**`probe`** — live probing against real endpoints, gated as follows. A TOML config names each
target and must declare `authorization = "own-account" | "written-permission"` and a `contact`
string. The command additionally requires `--i-am-authorized`. Absent either, it refuses to run and
explains why. Rate-limited by default.

### Commands

| Command | Network |
| --- | --- |
| `transit serve-hostile [--scenario <name>]` | local only |
| `transit differential [--corpus <dir>]` | none |
| `transit fuzz --target <url>` | defaults to the local hostile server |
| `transit classify --spec <openapi.json>` | none |
| `transit probe --live --config <targets.toml> --i-am-authorized` | yes, gated |

### Acceptance tests

1. `differential` detects the duplicate-key divergence between at least two parsers on the host.
2. `fuzz` against `hostile-server` in its default-injection scenario reproduces the parameter
   defaulting policy bypass: a payload the policy layer approves and the endpoint executes
   differently.
3. `fuzz` against the non-idempotent scenario reproduces the retry ambiguity — one branch where the
   client believes the operation failed though state changed, one where it executes twice.
4. `classify` on an ISO 20022 or S3-with-If-Match style spec returns `Qualified`; on a Slack
   `chat.postMessage` style spec returns `Non-qualifying`.
5. `probe` exits non-zero with an explanatory message when the authorization declaration is absent.

## occultation — P05 unlinkable identity

### Purpose

Measure what verifiable unlinkability costs at agent action rates, and test the pre-computation
scheme the whole design depends on.

### What is real and what is modelled

**Real:** Ed25519 baseline via `ed25519-dalek`; BLS12-381 pairings via `blstrs`; BBS+ presentation
and verification; the pre-computation pool; the anonymity-set calculator.

**Modelled:** ECDAA and threshold ElGamal escrow, behind `trait AnonymousAttestation` and
`trait EscrowTag`. Stub implementations carry the correct interface and representative cost
profile but provide **no security whatsoever**. The README says so at the top, and the stubs log a
warning when executed.

### Commands

| Command | Purpose |
| --- | --- |
| `occultation bench` | primitive costs against the Ed25519 baseline |
| `occultation bench --composed` | presentation **and** verification against the 15 ms budget |
| `occultation pool --burst <rate> --duration <t>` | pre-computation pool under load |
| `occultation anonymity --fleet <fleet.toml>` | anonymity set size given TCB configuration diversity |

`--composed` exists specifically to reproduce the arithmetic the desk study missed: presentation
and verification were each assessed separately against the budget and each looked acceptable, but
their sum exceeds it. `pool` addresses the security question nobody has asked — whether exhaustion
under burst forces a latency stall that leaks timing, or blinding-factor reuse that breaks
unlinkability outright.

### Acceptance tests

1. `bench --composed` reports a total exceeding 15 ms without pre-computation, and under 15 ms with
   it. This is the paper's headline correction.
2. `pool` under a burst rate exceeding refill rate reports exhaustion, and the tool's behaviour on
   exhaustion is **stall, never reuse** — asserted by test, because reuse silently breaks the
   security property.
3. `anonymity` on a fleet with a single TCB configuration reports a set size equal to the fleet;
   on a fleet with per-host TCB drift, it reports the partition sizes.
4. Stub implementations refuse to run without an explicit `--allow-modelled` flag.

## Papers

Each `paper/main.tex` reuses the Advanced AI Society cover page, palette and prose register from
`ov-poc-standard/paper/main.tex`: plain declarative section titles, examples before abstractions,
explicit statements of what is not known.

**Written now:** the problem, related work, the formalism, and the method — the sections that do
not depend on unrun experiments.

**Placeholdered:** results and evaluation, marked visibly in the source and wired to files in
`results/` so the numbers arrive from tool output rather than being typed in. This mirrors the
discipline of `tools/build_paper_figures.sh`, where regenerating figures re-runs the generators so
a stale figure cannot outlive a data change.

Each `paper/README.md` carries a pre-submission checklist in the style of the existing one:
co-author consent, citation verification, numbers refresh, and venue metadata.

## Build order

Three repositories is three specs' worth of work; implementation proceeds in sequence.

1. **parallax** — self-contained, and the other two papers cite its vocabulary.
2. **transit** — largest surface area, but every component is independently testable offline.
3. **occultation** — depends on the most external cryptography and carries the most modelled
   surface, so it benefits from the conventions the first two establish.

The shared skeleton is built once with parallax and copied forward.

## Risks

| Risk | Mitigation |
| --- | --- |
| `ascent`'s lattice support does not express the composition rules cleanly | Prototype the Σ₂ encoding first; fall back to a hand-written semi-naive fixpoint over the same lattice, which is a few hundred lines |
| BBS+ has no maintained Rust crate at the needed API | Implement presentation and verification over `blstrs` directly against the IETF draft; this is well-specified and is the measurement, not novel cryptography |
| `transit`'s live probing is misused despite gating | Gating is defence in depth, not a guarantee; the README states the operator is responsible, and the default target is always the local hostile server |
| Modelled stubs in `occultation` are mistaken for real | Stubs require `--allow-modelled`, log a warning, and the README leads with the distinction |
